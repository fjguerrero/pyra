# Pyra — UI: Fireworks analysis and 2026 proposal

## Fireworks' real UI (MX 2004 / CS6, the most mature)

Sources: the Fireworks MX UI guide, Fireworks MX 2004 manuals (O'Reilly / flylib),
quick-reference PDFs from the era, and **real screenshots analyzed visually**
(Fireworks CS6 on Windows 7 — Wikipedia; strips of the MX 2004 Tools panel).

Correction verified against the CS6 screenshot: the **Property Inspector goes at the TOP**, as
a horizontal strip under the menu bar (not in the right column). The right column
is the panel stack: document Properties → Align → Pages → Library/Layers.
**Page tabs go below the canvas**, not in a side panel.

- **Left toolbar** organized by mode sections:
  Select / Bitmap / Vector / Web / Colors (stroke+fill with swatches) / View
  (zoom, pan, screen modes). Picking a bitmap or vector tool switched
  the editing mode automatically — that was the hybrid heart of the app.
- **Property Inspector** — the defining panel. Purely contextual:
  - no selection → document properties (canvas size and color, "Fit Canvas" button);
  - with an active tool → that tool's options;
  - with a selected object → stroke, fill, effects, position/size.
  In MX it replaced half a dozen panels. Never modal, always visible.
- **Dockable panels on the right**: Optimize, Layers, Assets (symbol library),
  Frames and History (states/animation). Docked or floating,
  groupable — the origin of its reputation for density.
- **Layers panel**: hide/show, lock, rename, duplicate, reorder with
  auto-scroll. Simple and complete.
- **Document window** with Original / Preview / 2-Up / 4-Up buttons for export previews.
- **Aggressive shortcuts**: F8 (convert to symbol), F4 (hide), Ctrl+0 (fit all),
  Ctrl+G (group), etc. Dialog-free flow.
- **Smart guides** (CS4+): automatic magnetic guides to object edges/centers
  during dragging, plus manual guides with snapping.

## What to recover and what not to

Recover:
1. **Property Inspector as the main right-hand panel** — contextual
   (document → tool → object). It is the most recoverable idea; nobody has
   copied it well since.
2. **Left toolbar by sections**, but without an explicit "bitmap vs vector mode":
   in Pyra the object carries its own nature; the tool only creates or edits.
3. **Layers as a permanent panel** in the right column, not modal.
4. **Pages** as a screen browser in the right column.
5. **Smart guides + snapping** as the default drag behavior.
6. Keyboard shortcuts first, no modal dialogs.

Discard:
- Floating/groupable panels (1998 freedom, chaos in practice).
- Optimize / slices / HTML export (discarded by the user).
- Frames and History as-is (states can be picked up later).
- Dense Creative Suite-style top menus.

## Pyra wireframe (2026 look)

Respects Fireworks' real geometry (verified in the CS6 screenshot), modernized:

```
┌──┬──────────────────────────────────────────────────┬─────────┐
│  │ Contextual Inspector (doc · tool · object)       │ LAYERS  │
│T ├──────────────────────────────────────────────────┤         │
│O │                                                  ├─────────┤
│O │              CANVAS                              │  PAGES  │
│L │        (pan/zoom, smart guides)                  │ (library.)
│S │                                                  │         │
├──┼──────────────────────────────────────────────────┴─────────┤
│  │ status bar: position/size · zoom · selection               │
└──┴────────────────────────────────────────────────────────────┘
```

- Inspector on top (like real Fireworks), right columns for layers/pages.
- Page tabs under the canvas as in FW, or in the PAGES panel — decide in M1.

- **Dense dark theme**, linear iconography, clean sans typography, native HiDPI.
- Fixed columns (no floating panels). Everything collapsible, nothing modal.
- Stroke/fill also accessible in the toolbar (as in FW).
- Thin status bar at the bottom with selection position/size (FW's Info panel).
